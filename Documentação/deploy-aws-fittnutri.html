Gerenciar EC2 (Ligar / Desligar)

⚡ Parar e iniciar a instância

Para economizar créditos, pare a EC2 quando não estiver usando. O EBS (disco) persiste — os dados do MySQL não são perdidos.

# ─── Parar EC2 (economiza compute, ~$0/h) ─── "/c/Program Files/Amazon/AWSCLIV2/aws.exe" ec2 stop-instances \ --instance-ids i-002dbbd8acdc50042 # ─── Ligar EC2 ─── "/c/Program Files/Amazon/AWSCLIV2/aws.exe" ec2 start-instances \ --instance-ids i-002dbbd8acdc50042 # ─── Aguardar ficar running ─── "/c/Program Files/Amazon/AWSCLIV2/aws.exe" ec2 wait instance-running \ --instance-ids i-002dbbd8acdc50042
💡 O Elastic IP é fixo — o domínio fittnutri.duckdns.org continuará apontando para 100.51.245.76 mesmo após reiniciar.
Conectar na EC2 (sem chave .pem)

🔑 EC2 Instance Connect

Como o arquivo .pem fica salvo no desktop de casa, usa-se o EC2 Instance Connect para injetar uma chave SSH temporária (válida 60 segundos) e conectar normalmente.

# ─── Passo 1: Gerar chave temporária (só na 1ª vez ou se sumir) ─── ssh-keygen -t ed25519 -f /tmp/ec2_temp_key -N "" # ─── Passo 2: Injetar chave via EC2 Instance Connect (60s para conectar) ─── "/c/Program Files/Amazon/AWSCLIV2/aws.exe" ec2-instance-connect send-ssh-public-key \ --instance-id i-002dbbd8acdc50042 \ --availability-zone us-east-1a \ --instance-os-user ubuntu \ --ssh-public-key "$(cat /tmp/ec2_temp_key.pub)" # ─── Passo 3: Conectar via SSH ─── ssh -i /tmp/ec2_temp_key \ -o StrictHostKeyChecking=no \ ubuntu@100.51.245.76
⚠️ Se o Windows reiniciar, a chave em /tmp/ec2_temp_key some. Basta rodar o Passo 1 novamente para recriar.
Renovar Credenciais AWS Lab

🔄 Por que as credenciais expiram?

O AWS Academy usa credenciais temporárias (STS) que expiram a cada sessão do Learner Lab (geralmente 4 horas). Existem dois lugares onde precisam ser atualizadas:

OndeO que para de funcionar
~/.aws/credentials (local) AWS CLI: start/stop EC2, EC2 Instance Connect
.env na EC2 Backend: upload de PDF para o S3

📋 Processo de renovação (4 passos)

1
Pegar novas credenciais no painel do AWS Lab

Acessar o Learner Lab → clicar em "AWS Details" → copiar os 3 valores: aws_access_key_id, aws_secret_access_key, aws_session_token.

2
Atualizar ~/.aws/credentials no computador local

Editar o arquivo C:\Users\lucas\.aws\credentials com os novos valores.

3
SSH na EC2 e atualizar o .env

Usar o processo de EC2 Instance Connect acima para entrar na EC2 e editar ~/FittNutri/.env com as novas credenciais.

4
Reiniciar apenas o container backend

O backend é o único que lê as credenciais AWS. Não é necessário derrubar o MySQL ou outros serviços.

# ─── Arquivo: C:\Users\lucas\.aws\credentials ─── [default] aws_access_key_id = NOVA_ACCESS_KEY aws_secret_access_key = NOVO_SECRET_KEY aws_session_token = NOVO_SESSION_TOKEN # ─── Na EC2: editar .env ─── nano ~/FittNutri/.env # Atualizar: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN # ─── Reiniciar só o backend ─── cd ~/FittNutri docker compose up -d --no-deps backend
Fluxo de Geração de PDF (RabbitMQ + S3)

📄 Como funciona o envio de dieta para o S3

O processo é assíncrono via fila. O backend não gera o PDF na hora — ele publica uma mensagem e um consumer processa em background.

Usuário clica "Enviar PDF"
→
GET /api/meals/patient/{id}/pdf
→
PdfProducerService
→
Fila: pdf.generation
→
PdfConsumerService
→
Upload S3
ComponenteArquivoDetalhe
Fila RabbitMQConfig.java pdf.generation · durável
Producer PdfProducerService.java @Profile("prod") · publica PdfGenerationMessageDTO
Consumer PdfConsumerService.java @Profile("prod") · @RabbitListener · gera PDF → S3
Broker application-prod.properties spring.rabbitmq.addresses=${RABBITMQ_URL}
✅ O backend já está conectado ao CloudAMQP (plano Little Lemur · gratuito). A variável RABBITMQ_URL está configurada no .env da EC2. Nenhuma alteração necessária.
Rebuild Completo dos Containers

🔨 Quando usar: nova versão do código ou mudança de configuração

# ─── Puxar código mais recente ─── cd ~/FittNutri git pull origin main # ─── Rebuild + restart ─── ./manage.sh rebuild # ─── Acompanhar logs durante o build ─── docker compose logs -f backend docker compose logs -f frontend
⚠️ O build do frontend (Vite) consome muita memória. A EC2 possui 2 GB de swap configurado em /swapfile. O NODE_OPTIONS=--max-old-space-size=1024 já está configurado no frontend/Dockerfile.
💡 Se a EC2 foi recriada do zero (novo Terraform), recriar o swap antes do rebuild:
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
Certificado SSL (Let's Encrypt)

🔒 Renovar certificado (expira 2026-06-22)

O Certbot precisa ser rodado manualmente quando o certificado estiver próximo de expirar.

# ─── Rodar Certbot para renovar ─── cd ~/FittNutri docker compose run --rm certbot certonly \ --webroot -w /var/www/certbot \ -d fittnutri.duckdns.org \ --email lucas.cartaxo@sptech.school \ --agree-tos --no-eff-email --force-renewal # ─── Recarregar nginx após renovar ─── docker compose exec nginx nginx -s reload
